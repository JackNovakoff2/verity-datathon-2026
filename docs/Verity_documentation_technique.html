Verity : chaque chiffre a un reçu

Note technique. Un mandat client codé et confirmé, un portefeuille simulé, des reçus recalculés par deux implémentations, un gouverneur et un vérificateur. Simulation uniquement.

Point-in-time. Le portefeuille d'une date de décision n'utilise que les prix ≤ cette date : volatilité = écart-type des rendements quotidiens × √252 sur les 252 séances qui précèdent. Un test détruit tous les prix postérieurs (multipliés par 0,2 à 3,2 au hasard) : les poids restent identiques à 10⁻¹² près. La date par défaut est le 30 décembre 2022, fin d'une année où actions et obligations ont baissé ensemble. Hypothèses : achat à la date de décision, conservation, sans frais, impôt ni rééquilibrage.

3. Double calcul et reçus

Phrase publiée : « Sa volatilité annuelle, mesurée sur l'année qui précède, est de 8,2 %, sous le plafond de 8,5 % fixé par le mandat. »
Reçu vol:p_trail : Écart-type échantillonnal des rendements quotidiens × √252. Période du 2021-12-17 au 2022-12-30 (252 séances), 16 titres (dont ZST.TO 34,1 %, XIU.TO 8,7 %, SPY 6,1 %…).
Calcul A = 0.0820382305 · calcul B = 0.0820382305 · concordance : oui.
Données : prix ff2a3f2d0a7d, change f04e218ac5b0 (SHA-256 tronqués).

Chaque phrase du récit contient des jetons {{fait}}. Le vérificateur remplace le jeton par la valeur du fait et rejette le texte s'il reste un chiffre libre. Le cas de Robert produit 32 faits, tous vérifiés. Le bouton « Tester la vérification » de l'application montre trois rejets : chiffre inventé (« +300 % »), jeton inconnu, et un jeton valide accepté.

Le reçu ouvert dans l'application : double calcul, formule, période, titres, empreintes.

4. Gouverneur : le cas Robert / NVIDIA

Robert (59 ans, horizon 4 ans) a 6 règles. Il demande 50 % de NVIDIA ; le gouverneur compare à son mandat :

RègleAvec la demandeVerdict
Volatilité annuelle d'au plus 8,5 %26,2 %enfreinte
Aucun titre individuel au-delà de 5 %50,0 % (NVDA)enfreinte
Baisse historique maximale tolérée : 10 %34,6 %enfreinte

Volatilité 8,2 % → 26,2 % ; NVIDIA porterait 95 % du risque ; sa baisse historique seule avant la décision était de −63,5 %. Contre-proposition : 1,5 % au plus. Avec le recul, la demande aurait rapporté +568,4 % en passant par −33,9 % ; Verity le dit et rappelle que choisir le gagnant après coup n'est pas une stratégie.

Capture de l'application déployée : refus, sans et avec Verity.

7. Sécurité et conformité

  • Rôle de moindre privilège : la fonction ne peut qu'invoquer les modèles Bedrock Anthropic.
  • Entrées validées : mandat compilé par le modèle accepté seulement s'il passe le schéma strict ; récit tronqué à 1 500 caractères.
  • Aucun identifiant bancaire : l'application ne collecte aucun champ de ce type (scénario E2E 7).
  • Pas de secret dans le code ni dans les documents ; les accès AWS sont fournis par le rôle d'exécution.
  • Données fictives : profils inventés ; le récit saisi par l'utilisateur est transmis à Bedrock pour être traduit en règles.
  • Pas de conseil : bandeau « Simulation uniquement » toujours visible ; aucun ordre n'est exécuté.
  • Auditabilité : règles, refus et reçus sont rejouables depuis les empreintes des données.
  • Non revendiqué : aucune conformité réglementaire (valeurs mobilières, vie privée) n'est évaluée ici.

9. Faits, hypothèses, inconnues

Faits vérifiés
  • 31 actifs, 1 228 séances, du 2021-11-12 au 2026-11-12.
  • Robert : volatilité 8,2 % → 26,2 %, 3 règles enfreintes, contre-proposition 1,5 %.
  • 32 faits du cas Robert, chacun A = B.
  • 12 tests unitaires ; E2E 8/8 et 7/7.
  • Déployé sur Lambda, API Gateway, Bedrock.
Hypothèses
  • Achat à la date de décision, puis conservation, sans frais ni impôt.
  • Volatilité sur 252 séances précédentes.
  • Plafonds des mandats : valeurs de démonstration.
  • Univers de 31 actifs représentatif pour la démonstration.
Inconnues
  • La tolérance réelle au risque d'un client, qu'un récit ne mesure pas.
  • Le comportement hors de l'échantillon : rien n'est prédit.
  • L'effet sur de vrais clients ou courtiers : non mesuré ; la valeur visée (explication auditable) reste un objectif.

10. Limites honnêtes

  • Pas de point-in-time strict sur les prix : les cours sont ajustés a posteriori (dividendes, fractionnements) ; seule l'absence de regard vers le futur est garantie et testée.
  • Biais du survivant (univers choisi en 2026), chevauchement des FNB, 31 actifs seulement.
  • Pas de données ESG, de nouvelles ni de fondamentaux : l'exclusion « Énergie » est un substitut simple, sans accusation de controverse.
  • Aucune prévision de rendement et aucune performance future promise ; le « recul » décrit une période passée.
  • Latence : la rédaction par Claude prend environ 18 s et la compilation d'un récit libre environ 9 s (mesures de déploiement), sous la limite de 29 s d'API Gateway ; un gabarit déterministe prend le relais si le modèle échoue.
  • Démo éphémère : le compte AWS jetable expire le 16 novembre 2026 ; le film et les PDF restent les preuves durables.
  • La date de décision de l'étape 3 s'affiche « 1 janv. 2023 » alors que les reçus citent la séance du 30 déc. 2022 (dernière séance de l'année) : écart d'affichage constaté, sans effet sur les calculs.

11. Pistes

  • ESG et fondamentaux depuis des sources publiques (SEDAR+, EDGAR).
  • Données point-in-time strictes (prix non révisés).
  • Frais, impôts, rééquilibrage dans la simulation.
  • Mandat multi-objectifs (achat à court terme et retraite).
  • Signature cryptographique des reçus pour un audit externe.
  • Évaluation de la compréhension par un panel de clients, seule façon de mesurer un bénéfice réel.
